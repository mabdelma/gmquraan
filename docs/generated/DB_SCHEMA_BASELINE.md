## Monetary type audit

The specification forbids floating point for accounting amounts. Two representations
satisfy that: decimal/numeric, and integer minor units. This repository uses integer
minor units (`Int // cents`) in its payment models, which is sound, so only `Float`
is reported as a defect below.

No monetary field uses Float.

**Float defects: 0. Integer minor-unit fields: 12.**

Note for FIN-01: there is no `Decimal` anywhere in the schema today. A general
ledger with multi-currency and tax needs one money representation across the whole
domain, so which of the two to standardise on is a Wave 2 decision item rather than
something to settle per table.
